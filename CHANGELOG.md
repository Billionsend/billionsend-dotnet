# Changelog

## 0.3.0 (2026-11-20)

- The OpenAPI snapshot follows the published document (186 operations, 6 added).
- New resource `Brand`: `Brand.GetAsync` and `Brand.UpdateAsync` (the team's defaults for the hosted unsubscribe pages: `logo_url`, `accent_color`, `font` (`geist`, `system`, `serif`, `mono`), `company_address`, `powered_by`, `show_topics`, and the read-only `powered_by_locked` and `branding_locked`), `Brand.Logo.UploadAsync` and `Brand.Logo.DeleteAsync`. A write needs a key made by an owner or admin; a key held to one domain is refused with `403 restricted_api_key`.
- New: `Domains.UnsubscribePage.Logo.UploadAsync` and `DeleteAsync`, a domain's own logo on its unsubscribe pages. An upload is `multipart/form-data` with one `FileUpload` in the field `file` (PNG, JPEG or WebP, judged from the bytes, at most 2 MiB; the answer is `{ object: "logo", logo_url }`, a delete answers `{ object: "logo", deleted: true }`). `FileUpload`'s default content type is still `text/csv`, so pass `"image/png"` (or the image's own type). No logo storage answers `404`, a file the API refuses `422`. Like every multipart upload, a logo upload is not retried after a `5xx` or a dropped connection; a `429` is repeated after its `Retry-After`.
- A domain's `unsubscribe_page` answers `support_url` (an http(s) link, `null` for none), `powered_by` (`true`, `false`, or `null` to follow the team's default) and the read-only `powered_by_effective` (what recipients see: always `true` on Free, whatever is saved); `Domains.UpdateAsync` writes `support_url` and `powered_by` there. `logo_url` is `null` when no logo is stored.
- Broadcasts: `dormant_check` (default `true`: a contact who got 8 or more broadcasts and automation emails with no tracked open or click for 120 days gets a "still want these?" email instead, and is left out later if they do not confirm within 14 days; applies only on a sending domain with tracking on) and `include_dormant` (default `false`: `true` also sends to contacts marked dormant) are optional on `Broadcasts.CreateAsync` and `UpdateAsync` and always in the answer of `Broadcasts.GetAsync`.
- README: a section on the brand and the logos (compiled and run by the tests like the others).

## 0.2.2 (2026-11-19)

- The OpenAPI snapshot follows the published document (180 operations, none added or removed).
- Suppressions can name a whole domain: `Suppressions.CreateAsync(new { domain = "spam.example" })` and `Suppressions.Batch.AddAsync(new { domains = ... })` block every address at that exact domain (subdomains are not covered; consumer mailbox providers such as `gmail.com` are refused). An entry now carries `kind` (`email` or `domain`), `domain` and `removable` (`false` for a permanent bounce or complaint entry), and its `email` is `null` on a domain entry, so code that reads `email` from a list has to allow for no address. `Suppressions.ListAsync` / `ListAllAsync` take `kind` (`email` by default, `domain`, `all`).
- Domains: `custom_return_path` defaults to `bounce` and cannot be changed after the domain is created; `Domains.UpdateAsync` with it answers `422`.
- `Deliverability.GetAsync` answers a `domains` array: each sending domain's own standing (`status`, `tier`, `paused_by`, the rates, `pause_margin`, the counts and `window_days`).
- A new `403` name, `domain_sending_paused`: one sending domain is paused and the team's other domains keep sending (`sending_paused` is still the whole team). Both throw `PermissionDeniedException`; tell them apart by `Name`.
- Webhooks: `deliverability.warning` and `deliverability.paused` deliveries carry `scope` (`team` or `domain`) and `domain` (`{ id, name }`, `null` for the team). Deliveries come with the `User-Agent` `BillionSend-Webhooks/1.0` from `51.161.117.92`; the README says to let them through a WAF or Cloudflare in front of your endpoint.
- The live harness refuses, as it does for an address, a recipient at a domain the run put on the suppression list.

## 0.2.1 (2026-11-19)

- The OpenAPI snapshot follows the published document: 103 operations declare a `403` they did not (`Restricted API key: refused to … (restricted_api_key)`, an `ErrorResponse` body) and 74 more append what a restricted key is refused to their existing `403`; only the public `POST /agent/signup` has none. A `403` still throws `PermissionDeniedException`, and the tests throw each declared status for every operation.
- `Emails.Receiving.ListAsync`: the `inbox_id` query takes an inbox ID or its email address, as the `/inboxes/{inbox_id}` paths do (an address that does not exist or belongs to another team answers `404`, a malformed one `422`). The README example says so and a test sends both forms.
- The API now answers `404 not_found` (not `401 missing_api_key`) for any path that ends in `/`. The SDK's check that refuses an empty path argument before sending is unchanged.

## 0.2.0 (2026-11-19)

- The OpenAPI snapshot is the published document again (180 operations; `scripts/sync_openapi.py --check` fails CI when they differ, on every push and daily), so the methods and the tests follow the API that is live: `GET /usage` answers `emails.daily` / `emails.monthly`, `contacts`, `domains` and the rest instead of `limits`.
- New operations: `Automations` (create, list, get, update, remove, validate, duplicate, simulate, stop, metrics, `Runs` list / get / cancel), `Events` (create, list, get, update, remove, send), `Contacts.Imports` (create, list, get) and `Contacts.Segments.ListAsync`, `Domains.Claims` (create, get, verify), `Emails.ShareAsync` / `UnshareAsync`, `Emails.Attachments` (list, get), `Broadcasts.ClickedLinksAsync` / `RecipientsAsync`, `Logs` (list, get), `OauthGrants` (list, revoke), `Webhooks.Events` (list, get, replay, `Attempts.ListAsync`), `Webhooks.RotateSigningSecretAsync`, `ApiKeys.UpdateAsync` and `Inboxes.Agent.UpdateAsync`.
- `FileUpload` and `multipart/form-data` bodies for `Contacts.Imports.CreateAsync` (a file part, text fields, and objects or lists as their JSON text); a required query parameter (`Broadcasts.RecipientsAsync`'s `type`) is a required argument.
- Removed: `Unsubscribes.DeleteAsync` (a recipient's opt-out is permanent) and `Webhooks.RotateAsync`, replaced by `Webhooks.RotateSigningSecretAsync`.
- `ListAllAsync` iterators now cover all 33 cursor-paginated lists.
- Fixed: an event stream that closed before its first event (a quiet inbox's stream is closed about every ten minutes) reconnected without `Last-Event-ID`, so mail that arrived in the second between the two connections was never delivered; the stream now resumes from the position the server opens every stream with.
- Fixed: a successful answer with no body (a 204, say) is `null` instead of an error; your own request types leave an unset property out instead of sending `null`, which the API refuses; a multipart file name with non-ASCII characters is written as plain UTF-8 and one with a quote no longer throws; a path value of `.` or `..` is refused instead of being folded into another route.
- Fixed: an event stream whose connection goes silent without closing (a NAT or proxy dropped it with no reset) waited for ever; it now takes a connection that sends nothing for `EventStreamOptions.IdleTimeout` (default 45 seconds, the server's keepalive is every 15) for dead and reconnects from its cursor.
- Fixed: `Webhook.Verify` accepts a secret that ends in a newline and header values padded with whitespace, and splits a rotation's signatures on any whitespace; an empty list in a query parameter is left out instead of sent as `key=`; an API key or base URL read from a file or the environment is trimmed (a key of only whitespace is no key); a header value that cannot travel (non-ASCII or control characters, an `Idempotency-Key` with Unicode, say) is refused with the header's name before anything is sent, instead of failing as a network error and being retried.
- Fixed: a `429` is retried for every operation after its `Retry-After` (seconds or an HTTP date, never more than a minute), including a POST, PATCH or DELETE without an `Idempotency-Key`: the API answers it before it writes anything, so a repeat is safe. Before, only requests safe to repeat were retried and the others failed on the first rate limit; a `5xx` or a dropped connection is still retried only for those.
- README: the agent example handles only `inbox.email.received` (`inbox.deleted` and `inbox.expired` are not filtered by `types`) and runs in the tests.
- Tests: every answer of the fake API and every request is checked against the OpenAPI schemas, each operation is called with its own sample body and query and compared piece by piece, each declared error status is thrown as its type, coverage of the hand-written runtime is gated in CI (95% of lines and branches), and `tests/BillionSend.E2E` runs the SDK against the live API (not part of CI), and its harness refuses, before sending, any recipient but the SES simulator's success mailbox and any address the run put on the suppression list.

## 0.1.0 (2026-11-17)

- First version of the BillionSend SDK for .NET: every operation of the BillionSend API (139), grouped by resource and named after each operation's `operationId` (`client.Emails.Receiving.Attachments.ListAsync`), generated from the OpenAPI document with its descriptions as doc comments. `emails.metrics`, which is also the group of `emails.metrics.links` / `countries` / `clients`, is `client.Emails.Metrics.GetAsync`.
- Async methods that take any serializable request body and return the answer as a `JsonNode`; query parameters as a dictionary, lists sent comma-separated in one parameter.
- Errors as exceptions: `ValidationException`, `AuthenticationException`, `PermissionDeniedException`, `NotFoundException`, `ConflictException`, `RateLimitException` (with `RetryAfter`), `ApiException`, `ApiConnectionException` and `ApiTimeoutException`, all `BillionSendException`s with `StatusCode`, `Name`, `Message` and `RequestId` (the answer's `x-request-id`).
- The sending operations always carry an `Idempotency-Key`: the caller's, or a new one per call that its retries reuse.
- Retries for 429, 5xx, timeouts, network failures and `409 concurrent_idempotent_requests`, on requests safe to repeat; `Retry-After` honoured, exponential backoff otherwise; per-attempt timeouts; your own `HttpClient` if you pass one.
- `ListAllAsync` / `SearchAllAsync` iterators (`IAsyncEnumerable<JsonNode>`) over the 21 cursor-paginated lists.
- Inbox event streams (server-sent events) as `IAsyncEnumerable` of `InboxStreamEvent` and `StreamGapEvent`, resuming with `Last-Event-ID` after a dropped connection; `stream.gap` handed out once per position; one inbox's stream ends after its `inbox.deleted` or `inbox.expired`.
- `Webhook.Verify` checks a webhook delivery's signature and timestamp and returns the parsed event.
- `BILLIONSEND_API_KEY` and `BILLIONSEND_BASE_URL`; no dependencies beyond the .NET runtime; .NET 8 or later.
